# Контрольная точка 1: связный список и стек

Практикум по алгоритмам. Односвязный список, стек на его основе, проверка скобок
и калькулятор арифметических выражений. Всё написано на Java без
`java.util.LinkedList`, `java.util.Stack` и `java.util.Deque`.

## Запуск

Нужен JDK 17 или новее, Gradle скачается сам через wrapper.

```
gradlew test    # тесты
gradlew run     # прогон контрольных примеров из задания
```

На Linux и macOS: `./gradlew test`, `./gradlew run`.

На Windows проект лучше держать в папке без кириллицы в пути. Иначе Gradle
не находит тестовые классы (`ClassNotFoundException`), хотя они скомпилированы.


## Часть 1. Односвязный список

`SinglyLinkedList<T>` хранит ссылки на первый и последний узлы и счётчик
элементов. Благодаря ссылке на последний узел `addLast` работает за O(1),
а не за O(n), как было бы с проходом до конца списка.

| Операция | Сложность |
|---|---|
| `addFirst`, `addLast` | O(1) |
| `removeFirst` | O(1) |
| `contains` | O(n) |
| `size` | O(1) |

`removeFirst` на пустом списке бросает `NoSuchElementException`. Если удалён
последний оставшийся элемент, ссылка на хвост тоже обнуляется, иначе следующий
`addLast` прицепил бы узел к уже удалённому. `contains` сравнивает через
`Objects.equals`, поэтому работает и для `null`. Итератор написан анонимным
классом, список можно обходить в for-each.

Дополнительно есть `getFirst()` и `isEmpty()`, они нужны стеку.

## Часть 2. Стек

`MyStack<T>` ничего не хранит сам, он делегирует всё списку (композиция,
а не наследование). Вершина стека находится в начале списка:

- `push` вызывает `addFirst`;
- `pop` вызывает `removeFirst`;
- `peek` вызывает `getFirst`.

Все три операции работают за O(1). Если держать вершину в конце списка, `push`
через `addLast` тоже был бы O(1), а вот `pop` стал бы O(n): у односвязного
списка нет ссылки на предпоследний узел, его пришлось бы искать от головы.

`pop` и `peek` на пустом стеке бросают `NoSuchElementException`.

## Часть 3. Проверка скобок

`BracketChecker.isBalanced(String)` проходит строку один раз. Открывающие
скобки кладутся в стек, закрывающая сравнивается с вершиной. Если стек пуст
или вид скобки не совпал, строка несбалансирована. В конце стек должен быть
пустым. Остальные символы пропускаются. Время O(n), память O(n).

Значение из стека сначала присваивается переменной `char`, чтобы сравнивались
символы, а не ссылки на объекты `Character`.

## Часть 4. Калькулятор

`Calculator.evaluate(String)` поддерживает целые и десятичные числа, `+ - * /`,
круглые скобки и унарный минус (`-3 + 5`, `2 * -3`, `-(1 + 2)`).

Работа разделена на два шага.

1. Токенизация. Строка разбивается на числа, операторы и скобки. Здесь же
   проверяется корректность: после числа или `)` должен идти оператор или `)`,
   в остальных местах ждём число, `(` или унарный минус. Так ловятся `2 3`,
   `2 +`, `()`, лишние и незакрытые скобки, посторонние символы.
2. Вычисление на двух стеках, числа и операторы (алгоритм Дейкстры,
   «сортировочная станция»). Число сразу кладётся в стек чисел. Перед тем как
   положить оператор, со стека операторов снимаются и выполняются все, у кого
   приоритет выше или такой же (для левоассоциативных `+ - * /`). На `)`
   выполняется всё до ближайшей `(`. В конце выполняются оставшиеся операторы.

Почему этот алгоритм. Он за один проход учитывает приоритет и скобки, работает
за O(n) и использует только стек, который уже есть. Рекурсивный спуск тоже
подошёл бы, но тогда стек был бы неявным (стек вызовов), а в задании нужен
свой. Перевод в обратную польскую запись с отдельным вычислением дал бы тот же
результат, но за два прохода и с промежуточным списком.

Приоритеты: унарный минус 3, `* /` 2, `+ -` 1. Унарный минус
правоассоциативный, поэтому `- -4` даёт 4.

Ошибки:

- деление на ноль (в том числе `1 / (2 - 2)`) даёт `ArithmeticException`
  с сообщением «Деление на ноль.»;
- некорректное выражение даёт `IllegalArgumentException` с описанием проблемы
  и позицией символа.

## Контрольные примеры

| Вход | Результат |
|---|---|
| `isBalanced("(a + b) * [c - d]")` | true |
| `isBalanced("{[()()]}")` | true |
| `isBalanced("([)]")` | false |
| `isBalanced("((a + b)")` | false |
| `isBalanced("")` | true |
| `evaluate("3 + 4 * 2")` | 11 |
| `evaluate("(3 + 4) * 2")` | 14 |
| `evaluate("10 / 2 - 3")` | 2 |
| `evaluate("2 * (3 + (4 - 1))")` | 12 |
| `evaluate("5 / 0")` | ArithmeticException |

Все они, а также пустые структуры, один элемент, повторное удаление из пустого
стека и некорректные выражения, покрыты тестами (70 штук).
